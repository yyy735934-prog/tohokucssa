# “组个局”部署清单

更新日期：2026-09-04

## 自动发布

Cloudflare Workers Builds 已连接 `yyy735934-prog/event-platform`。合并或直接推送到 `main` 后会自动执行：

1. `npm test && npm run build`
2. `npx wrangler d1 migrations apply event-platform-db --remote`
3. `npx wrangler deploy`

构建历史和日志位于 Cloudflare Dashboard 的 `event-platform` → `Deployments` → `Builds`。

## 本地手动发布

1. 使用拥有 `event-platform-db`、`event-platform` Worker 和 `events.tohokucssa.org` 域名权限的 Cloudflare 账户登录 Wrangler。
2. 确认 `npx wrangler d1 info event-platform-db` 返回的数据库编号与 `wrangler.toml` 一致。
3. 运行测试、生产构建和发布预检：

   ```powershell
   npm test
   npm run build
   npx wrangler deploy --dry-run
   ```

## 数据库迁移

现有线上结构已经记录为 `migrations/0001_existing_schema_baseline.sql`。以后不要继续直接执行仓库根目录里的旧迁移文件；请通过 Wrangler 创建新的、可向前兼容的迁移：

```powershell
npx wrangler d1 migrations create event-platform-db <migration-name>
```

将生成的 `migrations/*.sql` 与代码一起提交。自动发布会依据 `d1_migrations` 记录，仅应用尚未执行过的文件。

如需手动处理历史版本，先备份，迁移成功后再发布 Worker：

```powershell
New-Item -ItemType Directory -Force .wrangler\backups
npx wrangler d1 export event-platform-db --remote --output .wrangler\backups\event-platform-before-gatherings.sql
npx wrangler d1 execute event-platform-db --remote --file migrate-gatherings.sql
npx wrangler d1 execute event-platform-db --remote --file migrate-multiple-gathering-hosts.sql
```

迁移后核对新增表：

```powershell
npx wrangler d1 execute event-platform-db --remote --command "SELECT name FROM sqlite_master WHERE type='table' AND name IN ('gathering_templates','gathering_jobs');"
```

`migrate-gatherings.sql` 是一次性增量迁移，不应重复执行。

## 发布与线上检查

```powershell
npm run deploy
```

发布后依次检查：

1. 首页“正式活动 / 组个局”切换正常。
2. 管理后台可进入“每周组局模板”，新建草稿并批准。
3. Google 登录后可参加测试组局；密码登录不能参加。
4. 需要乘车的成员在分配前显示“乘车候补中”，且不计入有效人数。
5. 管理端分配座位后有效人数增加；达标后可确认最终时间和地点。
6. 管理页面能看到最近自动任务和失败原因。
7. 模板可上传活动图片；生成的本周组局默认带入该图，主理人可单独更换。
8. 成局后，组局后台可向确认成员发送通知邮件和带签到码的提醒。
9. 正式活动及组局后台均可生成并转发带报名二维码的海报。
